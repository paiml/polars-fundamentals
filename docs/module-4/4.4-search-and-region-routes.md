# 4.4 /wines/search and /wines/region/{region}

The last two endpoints look alike, since both find wines by text, and they are
deliberately different.

| Route | Matches | Case | Use it for |
|---|---|---|---|
| `GET /wines/search?q=bourbon` | substring of **name OR notes** | insensitive | a search box |
| `GET /wines/region/{region}` | the **whole** region string | exact | a link to one region's page |

## Search

```rust
async fn search_wines(
    State(state): State<AppState>,
    Query(search): Query<SearchQuery>,
) -> ApiResult<Vec<Wine>> {
    let lf = state
        .lazy()
        .filter(contains_ci("name", &search.q).or(contains_ci("notes", &search.q)));
    Ok(Json(to_wines(lf, clamp_limit(search.limit))?))
}
```

`.or()` combines two expressions exactly as `.and()` did in 4.2.

**Contract — search matches the name or the tasting notes:**

```rust
#[tokio::test]
async fn search_matches_name_or_notes() {
    let (_, by_name): (_, Vec<Wine>) = get_json("/wines/search?q=elk").await;
    assert_eq!(names(&by_name), vec!["Elk Cove Pinot"]);
    let (_, by_notes): (_, Vec<Wine>) = get_json("/wines/search?q=TOBACCO").await;
    assert_eq!(names(&by_notes), vec!["Achaval Ferrer Malbec"]);
}
```

**Contract — a search with no query is a client error, not every wine:** `q` is a
required field on `SearchQuery`, so Axum rejects the request before the handler runs.

```rust
#[tokio::test]
async fn search_without_q_is_rejected() {
    // ... GET /wines/search
    assert_eq!(res.status(), StatusCode::BAD_REQUEST);
}
```

## Region by path

```rust
async fn get_wines_by_region(
    State(state): State<AppState>,
    Path(region): Path<String>,
    Query(q): Query<LimitQuery>,
) -> ApiResult<Vec<Wine>> {
    let lf = state.lazy().filter(col("region").eq(lit(region)));
    Ok(Json(to_wines(lf, clamp_limit(q.limit))?))
}
```

Real region names contain commas and spaces (`Napa Valley, California`), so a
client percent-encodes them: `/wines/region/Napa%20Valley%2C%20California`. Axum
decodes the path segment before the handler sees it.

**Contract — the path route is an exact match:** `/wines/region/Mendoza` does not
return wines from `Mendoza, Argentina`. That is what `/wines?region=mendoza` is for.

```rust
#[tokio::test]
async fn region_path_is_an_exact_match() {
    let (_, wines): (_, Vec<Wine>) = get_json("/wines/region/Oregon").await;
    assert_eq!(names(&wines), vec!["Elk Cove Pinot"]);
    let (_, partial): (_, Vec<Wine>) = get_json("/wines/region/Mendoza").await;
    assert!(partial.is_empty(), "a substring must not match the path route");
}
```

**Contract — an unknown region is `200 []`, not `404`:** the region is a filter
value, not a resource that must exist.

```rust
#[tokio::test]
async fn nonexistent_region_is_an_empty_list() {
    let (status, wines): (_, Vec<Wine>) = get_json("/wines/region/Atlantis").await;
    assert_eq!(status, StatusCode::OK);
    assert!(wines.is_empty());
}
```

## Contract summary

| Section | Contract | Enforced by |
|---|---|---|
| Search | matches name OR notes, case-insensitive | `search_matches_name_or_notes` |
| Search | missing `q` → 400 | `search_without_q_is_rejected` |
| Region by path | exact match; percent-encoded names decode | `region_path_is_an_exact_match`, `region_path_decodes_spaces_and_commas` |
| Region by path | unknown region → `200 []` | `nonexistent_region_is_an_empty_list` |
