# 4.2 GET /wines: Query Parameters as Polars Expressions

Lab 5 filtered wines with `filter(col("rating").gt_eq(lit(90)))`. `GET /wines`
is that same idea, with the numbers coming from the URL:

```
GET /wines?region=napa&variety=red&min_rating=95&max_rating=98&limit=20
```

Every parameter is optional. Each one that is present adds one predicate.

## Building the predicate

```rust
pub fn wine_filter(f: &WineFilters) -> Expr {
    let mut predicate = lit(true);
    if let Some(region) = &f.region {
        predicate = predicate.and(contains_ci("region", region));
    }
    if let Some(variety) = &f.variety {
        predicate = predicate.and(contains_ci("variety", variety));
    }
    if let Some(min) = f.min_rating {
        predicate = predicate.and(col("rating").gt_eq(lit(min)));
    }
    if let Some(max) = f.max_rating {
        predicate = predicate.and(col("rating").lt_eq(lit(max)));
    }
    predicate
}
```

Starting from `lit(true)` is what makes "no parameters" mean "every row" without
a special case. The extra `true AND` term is evaluated once per
row and costs next to nothing.

**Contract — bounds are inclusive and combine with AND:** `min_rating=91&max_rating=92`
returns wines rated 91 and 92, and never a wine that satisfies only one bound.

```rust
#[tokio::test]
async fn wines_rating_bounds_are_inclusive_and_combine_with_and() {
    let (_, wines): (_, Vec<Wine>) =
        get_json("/wines?variety=red&min_rating=91&max_rating=92").await;
    assert_eq!(names(&wines), vec!["Louis Jadot Beaune", "Catena Zapata Malbec"]);
}
```

This test is not decorative. Delete the `max_rating` branch above and it fails:
the 94-point Malbec comes back.

## Text matching without SQL

The API this module is modelled on built SQL with `format!`:
`format!("region LIKE '%{}%'", region)`. That is an injection hole with an escape
function taped over it. Here, the user's text only ever reaches `lit()`:

```rust
fn contains_ci(column: &str, needle: &str) -> Expr {
    col(column)
        .str()
        .to_lowercase()
        .str()
        .contains_literal(lit(needle.to_lowercase()))
}
```

`contains_literal` treats its argument as plain text, not a regular expression,
so `.` and `*` in a query mean dots and stars.

**Contract — a parameter is data, never code:** a region string shaped like an
injection is simply a region no wine has.

```rust
#[tokio::test]
async fn wines_region_value_is_data_not_code() {
    let (_, wines): (_, Vec<Wine>) = get_json("/wines?region=x%27%20OR%201%3D1").await;
    assert!(wines.is_empty());
}
```

## Empty is an answer, not an error

**Contract — a filter that matches nothing returns `200 []`:**

```rust
#[tokio::test]
async fn wines_min_rating_above_every_rating_is_an_empty_list_not_an_error() {
    let (status, wines): (_, Vec<Wine>) = get_json("/wines?min_rating=99.5").await;
    assert_eq!(status, StatusCode::OK);
    assert!(wines.is_empty());
}
```

## Sorting and limiting

The gold layer holds tens of thousands of wines. Every list endpoint sorts by
rating (then name, so ties are deterministic) and returns at most `limit` rows:
100 by default and never more than 1,000.

```rust
fn clamp_limit(limit: Option<u32>) -> u32 {
    limit.unwrap_or(DEFAULT_LIMIT).min(MAX_LIMIT)
}
```

**Contract — the limit is applied after sorting and is capped:**

```rust
#[test]
fn limit_is_clamped() {
    assert_eq!(clamp_limit(None), DEFAULT_LIMIT);
    assert_eq!(clamp_limit(Some(5)), 5);
    assert_eq!(clamp_limit(Some(1_000_000)), MAX_LIMIT);
}
```

## Contract summary

| Section | Contract | Enforced by |
|---|---|---|
| Building the predicate | bounds inclusive, parameters combine with AND | `wines_rating_bounds_are_inclusive_and_combine_with_and` |
| Text matching | a parameter is data, never code | `wines_region_value_is_data_not_code` |
| Empty is an answer | no match → `200 []` | `wines_min_rating_above_every_rating_is_an_empty_list_not_an_error` |
| Sorting and limiting | limit applied after sort, capped at 1,000 | `limit_is_clamped`, `wines_limit_truncates_after_sorting` |
