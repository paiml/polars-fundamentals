# 4.1 An Axum Server over the Gold Layer

Module 3 ended with a gold layer: every clean wine rated at or above a threshold,
exported to `gold_wines.csv` and `gold_wines.json`. A file is a snapshot. A
service answers questions. In this module the gold layer stops being something
you export and becomes something other programs can query over HTTP.

The design has one rule: **the server does not re-implement the pipeline.** It
calls the same code the `gold` subcommand calls, holds the result in memory, and
answers every request with a Polars expression over it.

## Reusing the gold layer

`gold` used to build its LazyFrame inline. We lift that into a function both
subcommands share (`wine-pipeline/src/pipeline.rs`):

```rust
/// The gold layer as a LazyFrame: every clean wine rated at or above
/// `min_rating`. `gold` exports it; `serve` answers HTTP requests from it.
pub fn gold_lazy(conn: &Connection, min_rating: f64) -> Result<LazyFrame> {
    Ok(load_clean(conn)?
        .lazy()
        .filter(col("rating").gt_eq(lit(min_rating))))
}
```

Nothing runs yet. A LazyFrame is a plan, and the plan is identical whether the
next step is `CsvWriter` or an HTTP handler.

## Starting the server

**Contract — gold floor:** every wine the API can return is rated at or above the
threshold that defined the gold layer. The server checks this once, before it
binds a port, and refuses to start on an empty gold layer rather than serving an
empty list that looks like a working service.

```rust
Commands::Serve { min_rating, bind, port } => {
    let gold = pipeline::gold_lazy(&conn, min_rating)?.collect()?;
    if gold.height() == 0 {
        anyhow::bail!(
            "gold layer is empty at --min-rating {min_rating}; run bronze and silver first"
        );
    }
    let lowest = gold.column("rating")?.f64()?.min().unwrap_or(f64::NAN);
    assert!(lowest >= min_rating, "gold floor violated: {lowest} < {min_rating}");
    println!("contract: gold floor (min rating {lowest} >= {min_rating}) OK");

    let addr = std::net::SocketAddr::new(bind, port);
    tokio::runtime::Runtime::new()?.block_on(serve::run(gold, addr))?;
}
```

Why `collect()` once at startup instead of per request? The gold layer is a few
megabytes and read-only. Materialising it once turns every request into work
over memory, not a SQLite read plus a cleaning pass.

## Sharing the frame across requests

Axum hands each handler a clone of the application state, so the state must be
cheap to clone. An `Arc<DataFrame>` is one pointer; cloning a `DataFrame` itself
clones reference-counted column handles, not the data (`wine-pipeline/src/serve.rs`):

```rust
#[derive(Clone)]
pub struct AppState {
    gold: Arc<DataFrame>,
}

impl AppState {
    fn lazy(&self) -> LazyFrame {
        self.gold.as_ref().clone().lazy()
    }
}

pub fn create_app(state: AppState) -> Router {
    Router::new()
        .route("/wines/search", get(search_wines))
        .route("/wines/region/:region", get(get_wines_by_region))
        .route("/wines", get(get_wines))
        .route("/regions", get(get_regions))
        .route("/varieties", get(get_varieties))
        .with_state(state)
}
```

**Contract — every handler starts from the whole gold layer:** a request's filters
can never leak into the next request, because each handler builds a fresh
LazyFrame from the shared frame. The test suite drives the router in-process,
with no port and no network:

```rust
#[tokio::test]
async fn wines_without_filters_returns_every_row_highest_rating_first() {
    let (status, wines): (_, Vec<Wine>) = get_json("/wines").await;
    assert_eq!(status, StatusCode::OK);
    assert_eq!(wines.len(), 5);
    let ratings: Vec<f64> = wines.iter().map(|w| w.rating).collect();
    assert_eq!(ratings, vec![94.0, 93.0, 92.0, 91.0, 90.0]);
}
```

## Try it

```bash
cargo run -p wine-pipeline -- bronze --input wine-ratings.csv
cargo run -p wine-pipeline -- silver
cargo run -p wine-pipeline -- serve --min-rating 90 --port 3000
# contract: gold floor (min rating 90 >= 90) OK
# Serving 28272 gold wines on http://127.0.0.1:3000
```

## Contract summary

| Section | Contract | Enforced by |
|---|---|---|
| Starting the server | gold floor: every served rating ≥ `--min-rating`; empty gold refuses to start | `assert!` in `main.rs` before binding |
| Sharing the frame | every handler starts from the whole gold layer | `wines_without_filters_returns_every_row_highest_rating_first` |
